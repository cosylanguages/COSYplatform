# Retrieval plan: general-it-b1

What each lesson should ask the learner to reactivate, computed from the block registry.
Spacing: return at +1, +2, then +4, +8, +12 lessons. Five questions per lesson at most,
resolved blocks and the longest-waiting ones first. This is an input to authoring stage 2,
not a substitute for it: a row here is a block to ask about, the question still has to be written.

- lessons: **65**, blocks: **500**
- scheduled returns: **320**
- lessons at the cap of 5: **64**
- lessons with nothing due: **1**
- blocks introduced too late to return: **4**
- unresolved blocks appearing in the plan: **5** (teachable, but not yet linked to COSYdata)

## Capacity: what five questions a lesson can carry

This course introduces **7.7 blocks per lesson**. The method returns each
block five times, so it needs **2378** returns; the schedule has room for
**320** (five per lesson), which honours **320** and defers
**2058**. A course of this length can hold roughly
**64** blocks at this budget.

That gap is not a bug in the planner, it is the arithmetic of the method: the current item load
is several times what a five-question retrieval slot can sustain, which is the mechanical reason
a third of the vocabulary is never asked about again. Either the load comes down, the retrieval
slot grows, or some blocks are accepted as recognition-only and marked as such.
